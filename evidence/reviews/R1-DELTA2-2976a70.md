## Remaining and new findings

### N1 residual — Medium: legacy sink compatibility loses approval binding

**Evidence:** `plugin/line/sms/delivery.py:193-209,364-380`; `plugin/line/engine/sealed.py:88-98`. The compatibility limitation is acknowledged in `docs/lanes/L4.md:233`.

**Concrete failure:** a supported three-argument sink wrapper pauses after L4 validates/releases a code under approval A. The owner replaces A with B for the same live call, changing the approved sender. The wrapper resumes and calls `send_secret_to_call` without a generation. Lines 91-92 adopt B's generation, so the loop accepts A's retained code under B and sends it. The unchanged prior reproduction observed exactly one such frame after replacement. This requires a legacy/instrumented sink; the shipped glue passes the current sink directly and is protected.

**Smallest fix:** make the expected approval generation mandatory at this security boundary. Refuse call sinks that cannot accept it; refuse missing generations in the real sealed sink instead of reading the current generation. Update the legacy compatibility test to expect refusal and add the replacement interleaving. Do not restore the lock across the blocking sink.

**Trial impact:** none with `sms_source: none`. That setting returns before OTP service/source/tool setup (`engine/hermes_glue.py:356-362`). Close this compatibility hole before claiming N1 fixed for every supported integration; it is not a blocker for the requested OTP-disabled trial.

### N2 — Medium: delayed digits request ignores owner handoff

**Evidence:** `plugin/line/server/ingress.py:249-256`; `plugin/line/engine/service.py:413-431`; `plugin/line/engine/voice_port.py:96-105`. The normal menu gate refuses presses in owner-connected state (`engine/machine.py:544-550`), and the preserving-TwiML helper already knows to return the conference during handoff (`:880-886`). The successful nonce path bypasses that state check.

**Concrete failure:** a valid menu press creates a redirect nonce while the call is on hold. Before its digits webhook is processed, the owner accepts takeover. The delayed webhook then consumes the still-valid nonce, returns `<Play digits="2"/>` followed by a new `<Connect><Stream>`, and increments the stream generation while the engine is `owner_connected`. This instructs the business leg to play menu keys and enter a voice stream instead of preserving the owner's conference. A queued legitimate webhook suffices; a holder of the requisite URL/credentials can also time its first use. Single-use protection does not make that first use valid after the state changes.

Supplemental loopback reproduction in both modes:

```text
delayed_digits_after_handoff signature status 200 state owner_connected plays_stored_2 True plays_injected_9 False stream True conference False generation_delta 1
delayed_digits_after_handoff fallback status 200 state owner_connected plays_stored_2 True plays_injected_9 False stream True conference False generation_delta 1
```

This proves the stale side-effect document and generation mutation. Competing redirects' exact ordering at real Twilio was not tested, so the duration or outcome of an actual conference interruption is not asserted. Replay of the same nonce correctly omits digits and returns the conference; a forged `Digits=9` parameter does not alter the stored `2`.

**Smallest fix:** immediately before consuming the nonce, refuse handoff/end-requested/non-menu states and return the appropriate conference/hangup/current document without minting a generation. Apply the same current-state check in the redirect port before calling the adapter, and discard pending menu plans when leaving an eligible state. Add a delayed-valid-nonce-after-owner-accept regression in both modes.

**Tests:** `tests/l1/test_r5_voice.py:203-248` tests a successful redirect, duplicate nonce, stale generation completion and stream reconnection, but never overlaps owner takeover. The end-to-end owner test at `:173-195` has no pending digits redirect. Neither catches this race.

**Trial impact:** none on ConversationRelay, whose session has no `VoiceCall`; the digits route refuses that session. Fix before enabling Media Streams with owner handoff.

## New ingress and voice-side-effect assessment

- **Media upgrade:** `server/ingress.py:258-289` requires the path secret, verifies the configured public WSS URL's signature in signature mode, requires a voice session, verifies the REST leg in fallback mode, then claims the current-generation media token. Failure does not downgrade modes. One attached socket is enforced by `engine/machine.py:226-237`.
- **Token separation/replay:** `engine/service.py:390-409,433-440,485-492` separates `media-gN` from `relay-gN`; `:317-328` issues random tokens and hashes them for storage. `store/db.py:332-346` checks expiry/kind and consumes under its lock. Tokens are bound to the call and current generation. Wrong kind, stale generation and reuse are refused. A token presented against the wrong call can be burned before call-ID comparison, but cannot authorize that other call; this needs possession of the token and creates no credential bypass.
- **Stream start:** `voice/controller.py:182-195` constructs the bridge with the expected provider CallSid; `voice/mediastreams.py:118-138` verifies format/SID before invoking the start handler and ignores frames before start. `engine/service.py:717-719` sets outbound expected SID; inbound construction supplies it at `:939`. The start frame is correlation, not a second credential. Subsequent frame sequence numbers are not replay protection; security relies on the authenticated socket and single-use upgrade token. No fresh dial or owner-approval interpretation of start/custom/DTMF fields was found.
- **Digits:** `server/ingress.py:249-256` uses the existing HTTP account/SID/signature-or-REST checks. `voice/dtmf.py:122-144` generates a random 60-second, per-call, single-use nonce for stored menu digits. `engine/service.py:418-431` never takes digits from webhook fields, and caches only the stream document so replay does not repeat `<Play>`. The missing state check is N2.
- **Voice side effects:** there is no voice-tool number/dial/transfer argument. `voice/tools.py:174-188,204-212` rejects unexpected arguments and routes owner ring, menu keys and OTP through the port. `engine/voice_port.py:60-87` calls the existing engine/L4 methods. Owner ringing still uses configured owner, scoped grant and destination authorization before `place_call` (`engine/machine.py:632-658`). The outbound path still authorizes the stored task destination (`engine/service.py:681-709`). OTP uses token plus generation and status-only output. `machine.py:593-606` checks at send; the media sealed implementation (`voice/controller.py:459-490`) queues local tones/cached clips without an intervening suspension or model call. The digits redirect targets the existing provider SID and a server-generated URL, creating no new leg, but needs N2's state gate.

**Fallback limitations:** L1's existing list (`docs/lanes/L1.md:298-336`) remains appropriate for the proposed ConversationRelay trial: path-secret disclosure permits forged events that REST cannot disprove, token races at admission/recovery, forged owner acceptance after the owner answers, and signed-request replay also needs application defenses. Extend the wording for Media Streams: a stolen media URL can win the first-upgrade race; a correct start CallSid proves no speaker identity; a leaked digits nonce can be consumed early; and an accepted HTTP response containing an unused current media token can disclose it to the requester. Invalid digits nonces do not authenticate the sender further: their response can contain current stream TwiML, just as `/answer` can. These follow the documented bearer-secret limitation, not an independent path-secret bypass. N2 affects both auth modes.
