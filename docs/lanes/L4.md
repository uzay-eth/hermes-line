## 0. Result

1. `spikes/s3-sms/` is ported to `plugin/line/sms/` (`line.sms`) with the contract surface, including `release_otp(task_id, consent_token, consent_store) -> SecretText | None`.
2. **A cleartext tool result cannot be kept out of Hermes history without a core change** (section 1). Delivery is therefore **sealed only**: the model never receives a code. The plugin has no tool, mode or code path that returns a code (a test fails if one reappears).
3. Two sealed tools. `line_otp_fill(task_id, targets)` types the code into the approved page; `line_otp_to_call(task_id, call_id, mode)` hands it to the approved live call through `line.engine.sealed.send_secret_to_call` (L1; stubbed here exactly as the contract names it).
4. **Consent binds sender, window and destination.** Destination = site origin for a fill, `call_id` + counterpart for a call. `approval_prompt(task)` is the text the owner prompt must show. The open page's origin is read and compared before anything is released.
5. Consent is checked with L2's real `line.policy.consent.ConsentStore`; the released-message set goes through `line.store.released_otps` (`add`/`contains`), with an in-memory stand-in until L1 merges.
6. After a release, the exact code is scrubbed from every later tool result, the final reply and `line.sms` logs (public hooks only). `tests/l4/`: 317 offline tests, green on Python 3.9.6 and on Hermes's 3.11; 42/42 mutation checks killed; a subprocess test runs the plugin against the **real Hermes core** in a throwaway `HERMES_HOME`.

### 1.4 Finding

A code returned as a tool result lands verbatim in `state.db`, its word-FTS index, archived twins, the REST/Desktop history, the API-server stores and (on an API error) a request dump, and goes out on `tool.complete`, ACP and webhooks. **This cannot be avoided from a plugin.** The only plugin-side option is to keep the code out of every tool result. Hence sealed delivery, the coordinator's decision of round 2.

## 2. The release design

### 2.1 Sealed delivery to a page: `line_otp_fill`

```
owner approves (L1/L2)  ─► prompt = approval_prompt(task)   # senders, window, "Type the code into the page at https://…"
                           ConsentStore.issue("otp_release", task_id, binding_for(task), ttl)
model: line_otp_fill(task_id, targets=["@e7"])       # the model supplies no token, sender, window or origin
  OtpDelivery.fill:  task registered? kind == fill? → read the open page's origin (browser_console
                     "window.location.origin" via ctx.dispatch_tool) → must equal the approved origin
                     (unreadable = refuse)           # before the phone is read or consent spent
  OtpService.attempt: dry-run match (sender AND window AND one unambiguous code AND message not in
                     released_otps) → lock { not released? → ConsentStore.consume(token…) → released_otps.add
                     → register exact value with the scrubber }
  sealed slot:       120 s, ≤4 attempts → BrowserTypeSink → ctx.dispatch_tool("browser_type",
                     {"ref": "@e7", "text": <code>}, task_id=<browser task>)   # registry-level, no hooks
  tool result:       {"status":"filled","filled_fields":1,"from":"A***ME","task_id":"t1"}
```

* One field gets the whole code; N fields (N = code length) get one character each; any other count is `target_mismatch` and the slot stays sealed.
* If typing fails, or the page moved to another site, the slot survives for a retry without a new SMS or approval; the origin is re-read on every attempt. After a successful fill or after 120 s the sealed copy is dropped.
* `post_tool_call` fires only for `line_otp_fill` (args: task id and refs; result: status JSON). `browser_type` and `browser_console` are dispatched at registry level, so no hook, webhook, UI event or history row sees their arguments (proven against the real core in `test_core_integration`).

### 2.2 Sealed delivery to a call: `line_otp_to_call`

```
model: line_otp_to_call(task_id, call_id, mode="dtmf"|"speak")
  OtpDelivery.to_call: task kind == call AND call_id == the approved call_id; if the engine supplies
                     counterpart_of(call_id), it must equal the approved counterpart  # before release
                     → same release path as 2.1 → dtmf requires digits (else mode_unsupported, slot kept)
                     → line.engine.sealed.send_secret_to_call(call_id, SecretText, mode) -> bool
  tool result:       {"status":"sent", …}
```

* The sink receives a `SecretText`, never a `str`. `False` (call not ready, or L1's sink not merged: the stub returns `False` and sends nothing) is `sink_failed` and keeps the slot for a retry.
* `CALL_TRANSCRIPT_MARKER = "[verification code sent]"` is exported for L1: that is all the call transcript, events and Desktop snapshot may record.
* **L1 must also refuse in `send_secret_to_call` a `call_id` whose live counterpart differs from the approved one** (L4 can only check this when L1 passes `counterpart_of`).

### 2.3 Consent and destination binding

`binding_for(task)` = `{"senders": sorted normalised rules, "window_start_ms", "window_end_ms", "destination": {"kind":"fill","origin":…} | {"kind":"call","call_id":…,"counterpart":…}}`, rebuilt from the registered task, never from caller input. A task cannot be registered without a destination, nor re-registered with different terms. `Destination.fill` accepts https (and http on loopback), drops default ports and paths, refuses credentials; `Destination.call` needs a safe `call_id` and an E.164 counterpart. Look-alike origins (`example.com.evil.net`, other port, http) do not match (tested).

L2's store spends a token on **any** `consume` that finds it, a mismatch included (`plugin/line/policy/consent.py`, `consume` pops first). `OtpService` therefore calls `consume` only at the moment a code is about to be released, after sender, window, message, destination and origin checks have passed. A wrong site, a late SMS or an ambiguous message never burns the owner's approval (tested).

### 2.4 What each path sees

| Path (section 1) | Sealed delivery |
|---|---|
| `state.db`, word FTS, archived twins, spillover, jsonl/spool, response store | status JSON only (task id, field count, masked sender) |
| `tool.started` / progress / `tool_calls.log` | task id, field refs or call id |
| `tool.complete`, ACP, API server, REST/Desktop history | status JSON only |
| webhooks, shell hooks, `post_tool_call` | status JSON only |
| later tool results (page snapshot, terminal echo, CDP eval) | exact code replaced by `[CODE]` before append/flush |
| final reply and the assistant row | exact code replaced by `[CODE]` |
| logs, request dumps, compaction, memory providers, background review | nothing to copy |
| `line.sms` log lines and audit events | masked sender, destination as `fill:<origin>` / `call:<id>:<masked number>`, no code |
| call transcript, events, Desktop snapshot | `[verification code sent]` (L1) |

### 2.5 Scrubbing

`ValueScrubber` keeps released values in memory only (TTL 1 h, ≤32 values) and replaces any appearance, including separated or fullwidth spellings (`7 3 9 2 0 4`, `739-204`, `７３９２０４`), with `[CODE]`. It is applied through `MaskingFilter` (every `line.sms` log record), `mask_for_transcript(text)` (for L1's call transcripts and summaries), and the two public hooks. `mask_codes` (shape-based) still runs after it, so a code that has not been released yet but is spoken on a call is masked too. Known limit: a letter-only code is invisible to shape masking until it is released. Cost: 0.27 s for a 1 MB result, bounded on hostile input (tested).

### 2.6 Alternatives rejected

| Alternative | Why not |
|---|---|
| Return the code in the tool result and scrub afterwards | rows are final once flushed (fact 6) |
| `pre_tool_call` "modify" substitution of a placeholder | the modified args reach `tool.started`, progress bubbles, `post_tool_call`, webhooks (facts 2-3) |
| Register the code with core's vault redaction registry | undocumented core import; does not cover the `state.db` row; sealed delivery makes it unnecessary |
| Rewrite or delete the row in `state.db` | forbidden for plugins (catalog rule 9) and against core's contract |

### 2.7 Core changes worth asking for (not required)

1. A public `ctx.register_redaction_values(values)` over `register_vault_redaction_value`: exact-value masking in logs, request dumps, compaction, memory providers, traces.
2. A public way to read the current page URL (today `browser_console(expression=…)`, which `browser.restrict_evaluate` can block, in which case fills are refused).


## 3. Residual leak risks

| # | Risk | Status |
|---|---|---|
| R1 | The model types into the wrong site: a prompt-injected page could ask for the field of a phishing form | **reduced, not closed; browser fill is OFF by default** (`otp_browser_fill`). Consent binds the origin; the top-level origin is read before the phone is read, immediately before typing, between boxes and right after typing, and a change stops typing with `origin_changed` and burns the sealed code. **Open residuals:** (a) the check is not atomic with the keystrokes: the page can navigate after the last probe and before `browser_type` lands, or between the final probe and the next event, and the probes only prove what the top frame was at those instants; (b) only `window.location.origin` of the top-level document is compared, so a cross-origin iframe on the approved page, or a stale `@ref` that now points into another frame/document, is not distinguished; (c) `browser.restrict_evaluate` can make the probe fail, which blocks fills (fail closed). Enabling browser fill needs the browser tool to enforce the approved document/frame origin at typing time |
| R2 | The model gives the code to the wrong call | **mitigated**: the call id is bound; L4 checks `call_id` and, when L1 passes `counterpart_of`, the live counterpart. **Open for L1**: `send_secret_to_call` must itself refuse a mismatching live counterpart |
| R3 | `transform_tool_result` is fail-open and skipped for blocked calls, timeouts/cancels, exceptions, non-string (multimodal) results, and when `safe_worker_enabled()` turns all hooks off (`hermes_cli/lifecycle.py` `invoke_hook`); the first string return among all plugins wins | residual. A page snapshot taken after typing is normally a plain string and is scrubbed |
| R4 | `post_tool_call` observers (webhooks, shell hooks) see the **untransformed** result when tools run concurrently (the sequential path hands them the transformed one; agent-read, `tests/plugins/test_transform_tool_result_hook.py:109-132`) | residual: only a snapshot taken after typing, only if the owner configured webhooks |
| R5 | The model reads the digits from a screenshot and mentions them in its reasoning text; reasoning fields are persisted and not passed through `transform_llm_output` | residual, low; reply text is scrubbed |
| R6 | The code is briefly in plugin memory (slot ≤120 s, scrubber ≤1 h) and in the browser tool's own subprocess call | Python strings cannot be zeroed; not verified whether the browser backend passes the text via argv |
| R7 | Released-message set lost on restart | **fixed by contract**: `line.store.released_otps` (L1, persisted). Until it merges `default_store()` falls back to memory and logs a warning. If the store cannot be written or read, nothing is released (`store_error`) |
| R8 | Android 17 may hide fresh codes from every non-default SMS reader for 3 h (S3 risk 1) | unchanged; surfaces as `no_message` |
| R9 | Heuristic extraction untuned on real traffic; two close codes → `ambiguous` | gates: sender, window, destination, single use, owner approval |
| R10 | Letter-only codes are not recognised by shape masking before release | exact-value scrub after release |
| R11 | `ConsentStore` is process-local (restart revokes approvals) and burns a token on any mismatch | by L2's design; L4 consumes only at release |

### Wiring for L1 (engine)

```python
from line.policy.consent import ConsentStore
from line.sms import (AdbSource, ApprovedTask, Destination, OtpService, OtpDelivery, BrowserTypeSink, BrowserOriginProbe,
                      CallSink, approval_prompt, binding_for, configure)
from line.sms.hooks import register
svc = OtpService(AdbSource(), audit=transcript_event)       # released = line.store.released_otps when present
delivery = OtpDelivery(svc, BrowserTypeSink(ctx.dispatch_tool), origin_probe=BrowserOriginProbe(ctx.dispatch_tool),
                       call_sink=CallSink(),                  # resolves line.engine.sealed.send_secret_to_call
                       counterpart_of=engine.live_counterpart)  # optional but recommended
configure(svc)                                                # for release_otp()
register(ctx, delivery, consent_store, consent_lookup=lambda task_id: engine.otp_token(task_id))
# owner approval:
task = ApprovedTask(task_id, senders, start_ms, end_ms, destination=Destination.fill("https://shop.example"))   # or .call(call_id, number)
show(approval_prompt(task))                                   # senders, window AND destination
svc.registry.register(task)
token = consent_store.issue("otp_release", task_id, binding_for(task), ttl_s)   # ttl_s ≤ 3600 (L2)
# call transcript / events / Desktop snapshot: record CALL_TRANSCRIPT_MARKER for a delivered code, never text
```

### Round 9 (send-and-measure: one probe SMS from the plugin line to the Fi phone)

* **Sender** `tools/coordinator/send_latency_probe.py` (coordinator only, reuses `twilio_ops.py` for credentials, `req`, `balance`, `mask`, `ALLOW`, `BORA`, `STOP_BALANCE`). Watching means the ready file was written by `otp_delay.py --probe-nonce` after its baseline poll, is fresh, and belongs to a live process; `--wait-ready` defaults to 120 s.

### Round 8 (wireless adb)

* **Targets.** `AdbSource(serial=…)` takes a USB serial, the mDNS service name of a wireless-debugging phone (`adb-<id>-<suffix>`, with or without `._adb-tls-connect._tcp`; adb itself needs the suffix and the source adds it) or `ip:port`. A configured serial is always passed as `-s`: a different phone attached is never used instead (tested). With no serial the old behaviour stays (adb's own "the one attached device"; several = error).
* **Recovery.** On "not found", "offline", a closed link, a non-zero adb status or a timeout, a network target gets ONE reconnect per fetch, bounded by `reconnect_budget_s` (10 s): `adb mdns services`, match the service name exactly (another phone is never adopted), validate `ip:port`, `adb connect`, retry the query once. The learned `ip:port` is tried first until it fails. Errors: `phone unreachable over Wi-Fi (asleep or off the network)`, `paired device not advertised on the network (…)`, `device unauthorized: accept the wireless debugging prompt on the phone, or pair again with adb pair` (unauthorized and "permission refused" are never retried). A failure always raises; an empty list only ever means the inbox is empty. `on_event` reports `reconnect_attempt` / `reconnected`.
* **Latency.** Measured on the real Pixel (Android 17) over Wi-Fi: `adb shell echo` 0.04 s, `getprop` 0.06 s, but one `content query` 2-6 s (spikes to 14 s) and even a bare `app_process` start 5-7 s: the phone spends ~0.4 s of CPU and waits the rest (runtime start-up on an idle phone). The old fetch ran `adb devices` + two `content query` (rows, then an id-only cross-check) = two phone-side starts (11.7 s, 4.3 s, 2.8 s, 8.5 s, 6.5 s in five consecutive fetches). Now a fetch is exactly **one** `adb shell` with one `content query`: no `devices`, no `getprop`, no second query. The R1-reviewed verification is kept and made stronger: the projection asks the provider for `length(address)` and `length(body)` and the parser takes exactly that many characters per field, so a forged `Row:` line in a body or a sender field can neither create nor swallow a message and any disagreement is a `ParseError`. Same live run after the change: median 5.3 s, p90 10.3 s, min 1.5 s, max 13.7 s (26 polls); the floor is the phone-side start of a single query. The release loop (`OtpService.attempt`) now counts its poll interval from the start of a read, so a slow read is not followed by another full wait. The Wi-Fi default timeout is 30 s (USB 15 s) so a slow read is not mistaken for a dead link. **What would still cut latency (owner/L1 choices, not done):** USB; or keeping the phone awake and charging (to be measured), since the delay is phone-side. Not done: overlapping two staggered reads (halves the wait on average, doubles phone load).
* **`otp_delay.py`** keeps watching through drops: each failed poll is a `drop` event (time, reason) once, the next good poll a `recovered` event with the down time, the source's reconnects are logged, the JSON has a `reachability` block (polls, ok/failed, drops, recoveries, reconnect attempts/ok, longest down) and `fetch_ms_all`. One poll = one plugin fetch (timed); the `date_sent` metadata query runs once per new message. A run in which no poll ever succeeds ends "never reachable" (exit 3).
* **Live check over Wi-Fi, 2026-11-05** (read only, no body, no code; `evidence/sms/`): `otp-delay-wifi-live-with-drops-20261105T210507Z.json` (3 min, 30 polls: 25 ok, 2 drops of 14.4 s and 20.6 s, both recovered by adb's own auto-reconnect; our 5 reconnect attempts found the phone "not advertised" or "not found" and did not connect; read latency median 4.7 s, max 13.5 s) and `otp-delay-20261105T212036Z.json` (3 min, 26 polls, 0 drops; median 5.3 s, max 13.7 s). No new SMS arrived in either, so the Android 17 delay itself is still unmeasured. Observed: while the phone sleeps its mDNS advertisement disappears and the TCP port may still answer, so `adb connect` is not what brings it back; it came back by itself within 15-25 s.
* **Tests** (+29): `AdbParsing` (length-prefixed, forged rows are data, tampered output refused, CRLF), `AdbSourceBehaviour` (one adb call per fetch, no fallback to another phone), `WirelessTargets`, `WirelessRecovery` (mdns + connect + one retry, learned route, not advertised, other phone, connect failure, bounded to one reconnect, timeout, unauthorized, budget, ip:port, USB never reconnects, address validation, no silent empty), `PollingInterval`, and the live-script tests (drop/recover, wireless reconnect log, never reachable, malformed reply). ### Round 5 (R1-delta N1, L4 half)

* `to_call` no longer holds `registry.gate` (a blocking threading lock) across the call sink. It validates the approval under the gate (generation, binding, destination, live counterpart, attempt budget), releases the gate, then calls `send_secret_to_call(call_id, secret, mode, approval_generation=<slot generation>)`, so a replacement that runs on the service loop while the sink waits for that loop can no longer deadlock, and L1 can re-check the generation on its loop right before queueing the frame. ### Round 4 (R1 review fixes)

* **H1, approval generation.** `OtpTaskRegistry` gives every registration a generation (`register()` returns it; identical re-registration keeps it; `forget` + `register` always makes a new one) and keeps the canonical binding (sender rules, window, destination). A sealed slot stores both. Replacement or revocation drops the slot at once (`registry.on_change`); independently, every reuse re-checks generation and binding and rejects a mismatch before either sink. `registry.gate` (re-entrant) is held by `register`/`forget`, by the consent commit, and by delivery from final validation through the sink call, so an approval cannot be replaced between the check and the delivery; a replacement waits for a delivery already in flight (which then completes under the old, still-valid approval).
* **M1, L4 half.** `attempt`, `release_otp`, `OtpDelivery.fill/to_call` take `approval_generation`; a value that differs from the registered approval (or from the slot's) returns `approval_changed` before the phone is read and without spending consent. `hooks.register(..., generation_lookup=…)` feeds the engine's pending-approval generation to the tool handlers; with a lookup wired, an unknown pending approval is refused. Without a lookup the check is not enforced (L1 must wire it).
* **Browser fill** is off unless `OtpDelivery(otp_browser_fill=True)`; `line_otp_fill` is then not even registered, so the model cannot call it. The call target is unaffected. Residuals are R1 below.
* **For L1:** `registry.register()` now returns the generation; pass `generation_lookup=lambda task_id: <generation of the pending approval>`; pass `otp_browser_fill=cfg.<setting>` to `OtpDelivery` (default False). L1's `test_registrations_match_manifest_and_touch_no_disk` lists `line_otp_fill` and must drop it from the expected set while the setting is off.
