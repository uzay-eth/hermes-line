## Integration contract for L1

- `line.policy.destinations.check_destination(raw, settings)` returns immutable `DestinationDecision(allowed, e164, reason)`. Accepts only exact canonical ASCII E.164 US geographic numbers on `settings.allowed_destinations`. Never strips characters or normalizes an ambiguous destination. Hard parsing/jurisdiction/Bora/service denies run before the allowlist. Even a hand-built settings object cannot override them. No emergency suffix matching on otherwise approved full numbers.
- `Settings.load(dict)` rejects unknown fields, unsafe allowlist entries, invalid times/zones, non-booleans, disabled approval/allowlist or a concurrency setting other than one. Defaults: `disclosure_enabled=True`, `recording_enabled=False`, `quiet_hours_enabled=True`, `quiet_hours_start="21:00"`, `quiet_hours_end="08:00"`, `owner_timezone="America/Los_Angeles"` (Can's current owner zone), `max_calls_per_line=1`, `allowlist_only=True`, `require_approval=True`, `allowed_destinations=()`. Other owners must configure their zone. No allowlist approval is pre-seeded.
- `quiet_hours.is_quiet(aware_datetime, settings)` converts to owner wall time; start inclusive/end exclusive, including DST folds/gaps. Naive datetimes fail. Explicit settings may disable quiet hours or change the window, never destination hard denies.
- `ConsentStore.issue(action, task_id, binding, ttl_s)` returns an opaque random capability; `consume(...)` atomically pops it and compares the full binding snapshot. Wrong action/task/binding, expiry at the boundary, reuse or restart returns False. A mismatch burns the token. TTL is positive and at most 3600 seconds; monotonic clock; capacity 1024; expired entries pruned. Store is process-local, not durable or shared across workers. Do not log or expose tokens in transcripts. Issue only after trusted owner approval. Bind destination, role, revision, line/call and operation parameters appropriate to the action; L2 cannot infer them from an arbitrary binding dict.
- `line.detect.Utterance(text, at_ms=0, speaker="business", last=True, turn_id=None)` uses elapsed milliseconds and a stable call-scoped event ID. `classify(window, context, ask_model)` and `HoldTracker(ask_model=None).update(utterance, context=None)` (alias `.feed`) return immutable `Detection(label, confidence, evidence)`. Confidence is ordinal `low|medium|high`, not a calibrated probability. Labels exactly match the contract. Use one tracker per call, serialized updates, and finalized adapter transcripts. `context` must be JSON-safe and already masked.
- Deterministic voicemail/beep-text, IVR, queue and repeat rules precede model invocation. Transcript silence remains UNKNOWN. A fresh explicit confirmation answer may establish human; otherwise the injected model must return high-confidence structured JSON with current-turn evidence and a recent Hermes live-person confirmation question (within 20 seconds), plus `contingent=true`. A bare hello/yes/speaking cannot become human even under an overconfident fake. Invalid/uncertain/failed model output becomes UNKNOWN. A model is never called for clear rules. No audio beep detector is claimed.
- Model request is JSON with `instruction`, indexed `turns` and `context`. Expected response: `{"label":"human","confidence":"high","evidence":[0,1],"contingent":true}`. L1 supplies the existing Hermes session and must apply its own bounded execution timeout/cancellation. No model/provider library is imported here.
- Tracker bounds: 12 utterances of at most 2000 characters; 128 phrase results; 256 recent finalized event IDs. Exact repeats reuse results without model work; repeated inconclusive long phrases become hold messages. Replayed recent IDs yield UNKNOWN; partial/final replacements work because partial IDs are not consumed. Bounded replay memory is not a durable side-effect ledger.

L1 must run the destination gate before approval display **and again immediately before every provider side effect**, including owner ring, retry, callback redial, transfer/participant, verification and TwiML targets. It must consume matching consent, enforce quiet hours and a per-line lock, and ensure call liveness independently of classification. L2 does not implement dialing, ring dispatch, signatures, DTMF authorization, a call deadline/watchdog, logging/masking, or the durable side-effect ledger. The adapter-shaped rejection harness verifies zero fake-provider calls for rejected inputs; it is not evidence that L1's entry points are wired.

## Open risks and coordinator follow-up

1. **Experimental detection:** rules miss 4/5 held-out human episodes; canned-model gating misses 1/5 (bare hello). That miss is deliberate abstention, not relabeled ground truth. The proposed no-missed-human release gate fails. Keep automatic takeover/ringing experimental pending existing-Hermes evaluation and confirmation workflow integration. Zero fixture false positives is not a guarantee about arbitrary recordings.
2. A recording can answer a static confirmation verbatim; transcript-only rules cannot prove personhood. Model mistakes/prompt injection and STT truncation can still confuse human confirmation. Dynamic task-contingent confirmation should be supplied by L1/Hermes. Human replies containing queue words can be conservatively missed.
3. No real-time 35-minute soak, acoustic/STT/TTS test, end-to-end Hermes run, live provider enforcement test, transport failure validation or actual owner ringing occurred. The virtual scripts and bounded-memory unit test do not establish real-time watchdog/session survival. All of those require coordinator-owned integration work and any relevant authorization.
4. US area-code metadata is an offline conservative static set, not a fetched authoritative registry. Unknown/new US NPAs, toll-free and US territories are denied. It does not prove a subscriber is owned by Can, identify forwarding endpoints, or enumerate every full-length emergency-service line. The exact trusted owner allowlist remains essential; no third-party destination is approved here. Review metadata before widening jurisdiction support.
5. Consent state is in memory; multi-process use needs a single consuming authority or transactional store integration. L1 must bind every relevant parameter and never issue a token on a model's request alone. Per-line concurrency and all dispatch-time checks belong in the engine. The synchronous model callback needs timeout/cancellation there.
6. Tracker replay memory is bounded; L1 must prevent older reconnect replays from reaching side-effect dispatch. Transcript evidence can contain sensitive text unless the adapter masks it first. No OTP handling exists in this lane.

No blocked owner question or decision block. Coordinator integration is needed; no out-of-scope file was changed to implement it.

### Diagnosis and resulting behavior

Read the masked transcript and detection events in
`evidence/trial/call_68921278eab742c6/trial.json`, plus the real engine confirmation
wiring (`plugin/line/engine/machine.py`, `_detect` / `_maybe_confirm`).
The greeting “Hi. How are you?” follows disclosure only. There is no live-person
question in that context, so UNKNOWN is retained as the safe candidate state:
the engine should ask its live-person question. This isolated case remains a
reported human miss, rather than changing its ground truth to UNKNOWN.

The second reply, “Yeah. It's me, [NAME]. But information you have about me?”,
follows “Am I speaking with a live person?” by **9739 ms** in the saved transcript.
The old deterministic confirmation rule matched only the full sentence
“yes i am a live agent / live representative / real person / human”. It missed
“yeah”, identity replies, short yes/speaking and questions back. The semantic
fallback produced no accepted high-confidence human classification; the evidence
records only UNKNOWN/low, not the raw model reply. The old greeting veto also
explicitly blocked model-based “yes” and “speaking” confirmations.

The detector now deterministically confirms ordinary affirmative, identity or
question-back replies as **human/high** after a direct live-person question,
with evidence containing both the question and reply. The elapsed-time window
is **0–10000 ms inclusive**, reduced from 20 seconds. Direct question grammar
replaces the old “mentions human and has a question mark” test. Only the first
final business reply may consume that context; a newer Hermes turn invalidates
it. Clear voicemail/IVR/queue rules retain priority; negative responses remain
UNKNOWN. Bare hello/hi without a substantive answer remains UNKNOWN. Short
proper names and explicit name introductions are supported without any identity
lookup or fixture-specific name in production rules.

Tracker cache keys include the actual confirmation question identity/time,
rather than just a boolean. A prior UNKNOWN cannot hide a new confirmation,
a new question can receive the same affirmative again, and cached HUMAN or a
replayed turn cannot extend the confirmation window or emit a second event.
The model protocol, ordinal confidence, bounded memory and approval gates are
unchanged. This revises the round 1 guidance that yes/speaking could never confirm.

### Policy behavior and L1 interface

`check_destination(raw, settings) -> DestinationDecision` is unchanged.
`Settings.load(policy_dict)` now accepts `blocked_destinations`, default empty,
and permits explicit `allowlist_only=False`. Defaults remain allowlist-only,
empty allowlist, approval required, recording off, disclosure/quiet hours on,
one call per line. Approval cannot be disabled even in open dialing mode.

The seven requested toll-free codes **800, 833, 844, 855, 866, 877, 888** pass
the jurisdiction gate. With allowlist mode on, an unlisted hotline remains
refused; listed hotlines pass. With that mode off, toll-free and supported US
geographic numbers can pass destination policy, still requiring normal consent
and all other dispatch gates. NANP toll-free is an explicit supported exception
to geographic US area-code metadata; geography/ownership is not inferred from it.

Permanent premium/pay-per-call refusals include NPAs **900 and 976**, and
**976 subscriber exchanges** in any otherwise supported area code. N11 area
codes/exchanges, emergency/short codes, noncanonical dial targets, unsupported
NANP jurisdictions and all non-US country codes (including international
premium examples) remain refused before allowlist evaluation. Neither settings,
allowlist membership nor consent can override these hard refusals.

The hard-coded protected number and its named deny constant/reason were removed
from production policy. `blocked_destinations` is an exact-number deny list,
checked after mandatory format/jurisdiction/service refusals and **before the
allowlist/open-mode choice**. A match returns `allowed=False`, `e164=None`,
`reason="blocked_destination"`. Empty lists impose no additional number-specific
refusals. The previous protected destination is now refused only when configured
in that list, absent from an enabled allowlist, or otherwise denied by policy;
no account/resource action was performed against it.

Blocklist **configuration entries** normalize ASCII spaces and dashes, US ten
digits, eleven digits beginning with 1, and explicit `+1` to the same E.164
value. Explicit full international `+country` entries may also be stored as
blocks, although international dialing remains denied. Invalid entries such as
URIs, post-dial instructions, extensions, wildcards, Unicode digits or short codes
raise ValueError at Settings loading. The stored list is an immutable tuple;
normalized duplicates are removed and caller mutation cannot alter it. The gate
also normalizes lists provided via a settings adapter and fails closed for a
malformed list. **Dial input itself remains canonical ASCII E.164**, preserving
S2's parser and avoiding new ambiguous dialing forms. A formatted alias supplied
as a dial target is refused; it cannot bypass the configured block.

Example for L1's policy config (synthetic number; never dialed):

```json
{
  "allowlist_only": true,
  "allowed_destinations": ["+18005550123"],
  "blocked_destinations": ["1 800-555-0123"]
}
```

The example loads, but the blocked entry wins over its allowlist membership.
L1 only needs to pass the list into the existing Settings.load path; this lane
adds no config plumbing or special case in engine/server/provider code.
`DialGate.preview` and `DialGate.authorize` already call the policy gate. L1
remains responsible for supplying the configured list at every dispatch boundary.
A previously minted DialPermit is not retroactively revoked by this patch;
the engine must continue authorizing immediately before provider dispatch.

### State, time and cache handling

Explicit bot evidence is retained independently of the 12-utterance window.
A fresh declaration resets boundary and pending confirmation state. Music and
hold results establish a party boundary and stop sticky continuation-of-bot
classification; an 8-second gap establishes the same boundary at the next
business utterance. A resolved HUMAN clears the old bot declaration for that
resolved party. The tracker keeps one business-speech timestamp and constant-size
flags in addition to its existing bounded history/cache/replay IDs.

The gap is between elapsed `Utterance.at_ms` transcript timestamps. Hermes speech
never resets the business-speech clock. Empty/music/non-speech markers do not
reset it; lexical filler words do. Partial lexical business speech updates the
clock but never consumes the final event ID or classifies an identity. Out-of-order
speech cannot move the clock backward. Relay provides transcript timing rather
than proof of an acoustic speaker change; no prompt timer or wall-clock sleep is
needed in these tests. Use one serialized HoldTracker per call with monotonic
elapsed timestamps, as before.

Phase-sensitive results bypass phrase-cache reuse. In particular, repeatedly
seeing `unknown/possible_new_party` cannot become a cached hold announcement and
manufacture a boundary that then promotes the named bot to HUMAN. A fresh
boundary cannot reuse a prior sticky-assistant result. Explicit bot history and
boundaries remain available after the recent transcript window has rolled over.
The model cannot override these deterministic ambiguous-party results.

Standalone `classify(window, ...)` derives available transfer/music/queue/gap
context from its supplied recent window. It cannot recover bot declarations
which the caller omitted from that window. Production L1 should keep using the
stateful tracker rather than constructing isolated windows per utterance.
